# 07 · 文档治理（一份事实源 + 过期可见）

> 文档地图与维护规则在 [`docs/README.md`](../docs/README.md)；本文件只写**做与不做的判据**。

## 铁律：同一个问题只在一处有答案

| 问题 | 唯一归属 | 其余位置只能写 |
| --- | --- | --- |
| 怎么用 / 值得用吗 | `README.md` | 指针 |
| 改了什么 | `docs/CHANGELOG.md` | 指针 |
| 为什么这么选、放弃过什么 | `docs/DEVLOG.md` | 指针 |
| **不能**怎么做 | `.clinerules/` | 指针 |
| 接口契约 | `docs/CAPABILITIES.md` | 指针 |
| 现状与欠账 | `docs/PROJECT-OVERVIEW.md` | 指针 |

**判断标准：同一句话在两处出现且都可能被改 = bug。** 代码头注释只留「为什么 + 指针」，
版本流水账只在 `CHANGELOG.md`。

## 写规则文档（`.clinerules/`）

- **症状 → 对策两列，不写原理详解**。检验标准：一个 AI 只看到报错文本，能不能在这张表里搜到解法。
- 报错原文照抄（如 `This Func cannot be used as an output variable. Specifically: edit`）——
  AI 检索的入口是报错信息，不是概念名。
- 已确定的偏好写成默认值 + 「不必再问」（见 `05` 开头），省掉每轮对齐。

## 写决策日志（`docs/DEVLOG.md`）

- 记**原话**，不改写成「用户想要…」；**代价行必填** —— 没有代价的决策看起来永远是对的，会诱使重犯。
- 「已放弃 / 已回退的方案」表是最高性价比投入：一行成本，省一次完整返工。
- 只追加不改写，记错了补 `[更正]`；单条 ≤ 30 行。

## 数字与指针

- **数字必须带口径**：写「57 个类」要能回答「哪天的 57」。易变数字（行数）宁可不写。
- 文件头留口径行：`口径：v2.8 / 2026-10-21`。**没有日期的数字等于假数字**。
- 计划类文档（`WORKBENCH-PLAN`）必须标注「数字是当时的快照」，否则会被读成现状。

## 搬 / 删内容之后

1. **反查引用**：`Select-String -Path README.md,docs\*.md,.clinerules\*.md -Pattern '旧章节名'`
   —— 本项目一次瘦身就失效了 4 处引用。
2. **跑 `tools\check-docs.ps1`**：相对链接存在 / `*.md` = LF / `*.ahk` = CRLF / README badge 与
   `Config.Version` 一致。**退出码 0 才算过**，别只读输出。

## 体量

- 单文件 > 600 行提示归档（见 `06`）；README 某节 > 一屏 → 拆 `docs/` 专题，正文留一句话版本。
- **文档进不了上下文就等于不存在**，而体积主要来自超长单行 —— 拆长行比删行更有效
  （本项目 README 121KB → 38KB 主要靠拆掉几个数千字符的单行）。
